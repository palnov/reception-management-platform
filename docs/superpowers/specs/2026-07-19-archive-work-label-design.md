# Design: обновление подписи работы в архиве в расчётках

## Цель

В Excel-расчётках заменить пользовательскую подпись `Работа в архиве` на:

`Выполнение доп.обязанностей в пределах рабочего времени в указанном объёме, ч.`

Изменение должно применяться при каждой генерации расчётки, в том числе при выборе уже прошедшего расчётного периода.

## Объём

- Обновить подпись в обычной расчётке (`SALARY_SLIP`), которую формирует `lib/report-service.ts`.
- Обновить подпись в отдельной детализации (`DETAILIZATION`), которую формирует `lib/report-detailization.ts`.
- Вынести подпись в общий экспортируемый модуль/константу и использовать один источник истины в обоих генераторах.
- Сохранить без изменений внутренний тип смены `ARCHIVE_WORK`, расчёт часов, начисление и данные прошлых периодов.
- Не менять подпись в редакторах графика и других интерфейсах, где пользователю нужно выбрать тип смены.

## Архитектура и поток данных

Тип смены `ARCHIVE_WORK` остаётся в базе и используется расчётным кодом как прежде. При запросе Excel через `/api/reports/excel` или пакетную выгрузку `/api/reports/batch-zip` `ReportService` рассчитывает значения выбранного периода и передаёт их в генераторы workbook. Генераторы подставляют общую константу в ячейку с названием начисления.

Так как подпись не хранится в исторических записях, миграция базы данных и изменение существующих строк не нужны. Старые расчётки получат новую подпись при повторной генерации.

## Обработка ошибок

Изменение не добавляет новых входных данных или ветвей расчёта. Существующая обработка ошибок API и пакетной генерации остаётся без изменений.

## Проверка

- Добавить регрессионные проверки, подтверждающие новую подпись в обычной расчётке и в детализации.
- Сохранить проверку существующих значений базы расчёта и начисления для `ARCHIVE_WORK`.
- Запустить соответствующие тесты, TypeScript-проверку и линтер/сборку в объёме, поддерживаемом проектом.
