# Дозапись в KPI и зарплате — дизайн

**Дата:** 2026-08-07
**Статус:** дизайн подтверждён пользователем

## Цель

Добавить помесячную ручную метрику «Дозапись» для каждого сотрудника: количество штук, доплата 50 ₽ за штуку. Метрика должна рассчитываться вместе с зарплатой и быть видна в KPI-таблице, выгрузке зарплаты и детализации доплат.

## Границы задачи

В работу входят хранение значения, ввод из KPI-таблицы, расчёт доплаты, экспорт и сохранность при резервном копировании. Отдельный журнал каждой дозаписи, даты отдельных операций и комментарии не создаются: система хранит только итоговое количество за месяц, как для открытия и закрытия Б/Л.

## Выбранный подход

В `MonthlyChecklist` добавляется целочисленное поле `additionalEntryCount` со значением по умолчанию `0`.

Это использует уже существующую модель ручных помесячных показателей (`sickLeaveOpening`, `sickLeaveClosing`, `cardCreation`) и одну точку сохранения — `/api/checklist`. Отдельная таблица была бы нужна только для учёта каждой операции по отдельности и не нужна для согласованного сценария ввода количества за месяц.

## Данные и миграция

- В Prisma-модели `MonthlyChecklist` появится `additionalEntryCount Int @default(0)`.
- Будет добавлена Prisma-миграция для SQLite с `INTEGER NOT NULL DEFAULT 0`.
- У всех существующих записей значение автоматически будет равно `0`, поэтому исторические расчёты не изменятся.
- Восстановление из серверной и локальной резервной копии будет читать поле с защитным значением `0`, если резервная копия была создана до этой доработки.

## Ввод и доступ

- На странице `/kpi` появится столбец «Дозапись» рядом с остальными штучными ручными показателями.
- В ячейке будет показываться количество (`шт.`) и, если оно больше нуля, рассчитанная доплата (`+50 × количество`).
- Менеджер сможет открыть ячейку кликом, ввести целое неотрицательное количество и сохранить его по потере фокуса или Enter; пустое значение означает `0`. Escape отменяет редактирование.
- Используются те же ограничения, что уже действуют для Б/Л: редактирование доступно только менеджеру и только пока месяц не закрыт. Сервер повторно проверяет права и статус месяца.
- Некорректное число не сохраняется и отображает существующее сообщение об ошибке ввода.

## Расчёт

Для каждого сотрудника и выбранного месяца:

```text
additionalEntryBonus = additionalEntryCount × 50
totalPay = существующая сумма выплат + additionalEntryBonus
```

Доплата не зависит от коэффициента часов и суммируется с доплатами за Б/Л, карточки и другими бонусами. Значение `0` не влияет на итог.

## Отчёты

- В Excel-листе «Зарплата» будет отдельный столбец «Дозапись» с количеством штук.
- В детализации доплат появится отдельная строка «Дозапись» с расчётной базой вида `N шт.` и начислением `N × 50 ₽`.
- Шаблон детализации будет расширен на одну строку: все следующие строки, итог и подписи сдвинутся вниз без изменения их содержания. Итоговая Excel-формула будет охватывать новую строку.

## Согласованность и ошибки

- Страница KPI, Excel-лист зарплаты и детализация используют одну и ту же формулу `count × 50`.
- API принимает и возвращает значение в том же объекте помесячного чек-листа, поэтому после сохранения UI обновляет локальное состояние без полной перезагрузки.
- Старые резервные копии и существующие строки без поля корректно интерпретируются как ноль.

## Проверка

Регрессионные проверки должны подтвердить:

1. Prisma-схема, миграция, API и клиент передают `additionalEntryCount`.
2. KPI-таблица показывает и редактирует количество, а расчёт добавляет `50 ₽` за штуку к итогу.
3. Excel-лист зарплаты содержит столбец «Дозапись».
4. Детализация показывает новую строку и включает её в итоговую формулу.
5. Линтер, проверка типов и существующие регрессионные тесты проекта проходят.
